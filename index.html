CAPABILITIES

What an agent can do in your projects

Most of an automation's life happens after the first build, and an agent helps at every stage. It works on the same project files and platform APIs you do, so the work lands in your project instead of in a chat transcript.

Design and build

Turn a process document into a design and a build plan. Then author RPA workflows, coded automations, agents, Maestro Flows, coded apps and API workflows, with Document Understanding and human-in-the-loop steps where you need them.

Review and test

Ask for a read-only review with findings and severities, generate test cases and evaluations, and have the agent run the Workflow Analyzer (Analyze Project) and confirm a local run before you accept the work.

Ship, operate and fix

Publish solutions to Orchestrator, work with queues, assets and jobs, and investigate failures from logs and run history.

WORKING EFFECTIVELY

An agent is a fast collaborator, not an autonomous developer

You set the goal and judge the result. Three habits make the difference.

Treat the output as a draft

Read the files, not the summary. The usual failure is work that looks complete but is partly stubbed.

Validate with Studio's own checks

Analyze Project and a local run are more reliable than an agent reporting that it is done.

Use it as a reviewer too

Ask for findings with severity and tell it to change nothing. Agents are good at spotting gaps and security issues.
